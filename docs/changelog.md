## 0.1.31 · 2026-10-30

一轮可靠性加固，均为既有行为的缺陷修正，不改变对外配置字段与协议契约。

- **额度取数不再可能永久卡住**：HTTP 回退的换发与 Cloud Code Assist 请求此前没有超时。并发刷新会合并到同一个在途 promise 上，一次挂起的请求就让额度药丸永远停在「读取中」，手动刷新也救不回来。现在各有 20 秒上限，超时折叠成可读的失败快照并释放在途状态。
- **401/403 重试改按状态码判断**：此前靠匹配错误文案里的 `HTTP 401` 字符串，文案一改就静默丢掉「换发后再试一次」。`QuotaError` 现在携带 `status`，判断只看状态码；非 401/403 的失败不再触发无谓换发。
- **非法代理不再让插件装载失败**：此前 apply 一开始就同步解析 `proxyUrl`，保存了非法地址后重启宿主，插件加载即失败——而修正它的设置卡片正是本插件贡献的，用户只能手改配置文件。现在装载期只告警并继续加载，真正用到代理时各自失败（启动 ACP 报 `AGY_INVALID_PROXY`）。
- **运行期代理地址变坏按 Promise 拒绝**：插件自身的 `fetch` 与 CLI 取数入口此前会在同步阶段抛错，调用方的 `.catch()` 收不到。现按各自契约返回 rejected promise，由既有的「折叠成可读错误」路径处理。
- **恢复会话失败时归还磁盘 claim**：认领会话映射后若启动失败，所有权会残留到卸载。新增 `SessionMapStore.unclaim`，恢复与建轮两条失败路径都归还，别的 worker 可立即接管仍有效的条目。
- **单条畸形 JSON-RPC 帧不再判死整条链路**：无法路由的消息此前抛 `PROTOCOL_VIOLATION`，被消息泵当成流读取失败，链路关闭、对外报 `LINK_CLOSED`，所有在途请求一起失败。现在只丢弃该帧并留痕，链路与在途请求不受影响。带 id 却缺 `result`/`error` 的畸形响应单独处理：命中在途请求时立即按 `AGY_PROTOCOL_VIOLATION` 拒绝它，而不是丢弃后让那个请求白等到超时。
- **中止错误码统一**：连接池的 `AGY_TURN_ABORTED` 改为与适配器、协议层一致的 `AGY_ABORTED`。两者同属 `AGY_` 前缀，原本就不会命中宿主的重试词表，此处只消除排障时的语义分叉。
- **zip 解压加压缩炸弹上限**：条目数、单条目与解压总量三道守卫，并在写盘前判定。中央目录谎报解压大小的包由 yauzl 的大小校验拦下（构造用例已覆盖）；另按实际流出字节数加了兜底，用于该校验被关闭或换实现时的纵深防御。官方包远低于上限。
- **细节修正**：OAuth client 元数据多份并存时按出现顺序配对（此前固定取第一个 secret，可能与所选 client id 不配套），同一 secret 重复出现时也不会配错；MCP 桥 Bearer 头改常数时间比较；`parseTokenState` 去掉重复查询；额度超时文案在不足 1 秒时报毫秒，不再显示「超过 0 秒」。
- **验证边界**：本地类型检查、38 个文件 / 658 项隔离测试与构建通过。真实 Desktop GUI、官方账号与非 Windows 实机未重新验收；未用真实官方 zip 或真实对端造过异常输入，畸形帧与解压上限均由构造用例覆盖。

- **验证边界**：本地类型检查、38 个文件 / 639 项隔离测试与构建通过；覆盖逐模型设置的草稿合并、只提交改动项、目录变化与只读状态，以及映射与档位路由。真实 Desktop GUI 与官方账号未重新验收。

## 0.1.26 · 2026-10-23

- **消息一致性**：同一 DSH 对话可增量复用 ACP 会话；在交付 `finish` 前提交输入与输出指纹，调用方立即结束读取也不会重发旧问题。编辑回答、外部模型输出或历史/路由变化时完整重建；去重后没有可发送增量也回退完整重建，不发空 prompt。
- **上下文去重**：仅省略已见且未变化的上下文，不再按 form 整类丢弃；新规则、变化快照、目录更新与状态回滚继续发送。
- **取消排空**：可选保留进程，但必须先取得正常停止应答；新轮不能撤销宽限。本地超时/运输错误仍回收。`cancelGraceMs=0` 的语义调整为不等待、立即回收，而非保留未确认连接。
- **统一空闲回收**：聊天、预热和目录发现均纳入计时；活动请求、工具 park 与取消排空不算空闲。一次性标题/压缩/发现会话结束后关闭；内存复用记录最多 64 条。
- **恢复映射 v2**：共享存储管理 worker 所有权与串行写入，只落盘 ID、计数和指纹；旧格式安全失效。正常空闲回收保留有效映射，恢复后校正并核对模型；选模响应不完整时安全失败但保留上一份有效目录。load 拒绝、超时或取消先清理旧连接，避免迟到回放混入新轮。
- **跨 Host 隔离**：恢复缓存使用排他租约，占用时仅降级磁盘恢复，不影响聊天。崩溃残留锁不自动抢占，确认相关 Host 退出后再处理。
- **设置与文档**：设置卡增加复用、恢复、取消保留与两个计时字段；数值校验和只提交修改项的行为一致。修正采样参数、token 轮换及缓存 TTL 的旧描述；5 分钟是插件资源策略，不是上游 TTL 保证。
- **验证边界**：补齐 finish 即 return、输出改写/外部模型、上下文变化、取消/空闲竞态、恢复失败/工具桥/选模、文件格式与共享所有权回归；本地 `npm run check` 通过（36 个文件 / 591 项）。发布不代表本机升级，真实上游与 Desktop GUI 仍需单独验收。

## 0.1.24 · 2026-10-22

### 日常使用

- **有界并发池**：默认最多 2 个按需启动的独立 worker，可设 1–4；同会话工具结果回原 worker。等待队列最多 64 项，默认 120 秒，支持取消；主对话优先于排队中的后台标题。
- **先登录再取模型**：「连接 / 登录 ACP」建立不发送 prompt 的发现会话，验证连接并读取目录。无 CLI 时也可从已有 ACP 登录态刷新；目录、上下文容量与图片能力跨 worker 同步。
- **原生图片输入**：通过宿主附件服务发送当前 / 历史消息与工具结果中的图片，协商上游能力，校验引用、媒体类型与字节数。支持 PNG、JPEG、WebP、GIF；已卸载图片明确说明没有像素。
- **可观测连接**：区分预热、登录、建会话、生成、等待工具与停止；设置页显示队列与分阶段耗时，药丸可直接预热。
- **更可靠的设置草稿**：远端更新保留 dirty 字段，仅提交修改项，显示冲突，遵守只读状态并防重复保存。

### 工具与可靠性

- 续轮检查模型、思考强度、system、工具 schema、完整历史与上轮输出；不兼容时取消旧 prompt 并按新历史重建。
- MCP 参数按 schema 修正常见无歧义别名；缺必填字段返回 `AGY_BRIDGE_INVALID_ARGUMENTS` 与签名，不进入 DSH。类型与取值仍由 DSH 最终校验。
- stdin 写入与响应等待共享 deadline / abort；阻塞写入、缺管道、构造失败与握手失败进入统一回收路径。
- 验证 ACP v1 版本与所需 MCP / image 能力；未声明能力不当作支持。
- 取消与失败撤销桥授权；通过宿主受管进程终止并等待退出，不能确认退出时不允许新进程覆盖跟踪状态。

### 运行与网络加固

- 下载流写临时文件，限制来源与重定向，校验 ZIP 路径与布局；保留手动二进制优先级。
- 补齐 macOS / ARM64 / POSIX `.par` 与 Linux 参数的官方发行布局映射；默认 server 仍为 **1.4.0**，不自动追最新。
- onefile 运行代码迁至用户级独立 `runtime/instance-*`，记录所有权，只清理确认已退出的本插件目录；未知历史目录不按 mtime 删除。
- 直接声明 `undici` 依赖，统一下载、OAuth 与 HTTP 额度代理；显式代理失败不静默直连，关闭插件持有的连接池。
- 补齐结构化 token、无 scheme 代理材料和错误日志的脱敏；CLI 路径支持显式配置、PATH 与重新探测。

### 文档

- 主页采用快速开始、功能亮点、能力边界与验证矩阵分层，详细契约移至 `docs/`。
- 补齐完整配置、环境变量、安装 / 更新区别、登录材料读写范围、排障与维护发布流程。
- 明确 npm 发布不代表本机安装；不提供不存在的 GitHub Release 下载入口，不把示意或隔离测试当成真实 GUI 证据。

### 验证与剩余限制

本次本地 `npm run check` 通过：**33 个测试文件、515 项测试、TypeScript 类型检查与构建**。覆盖假 ACP / MCP、真实 React 18 renderer 交互、池与续轮、图片映射、阻塞写入、安全回收和本地 SOCKS 代理测试。React renderer 不是浏览器像素验收；假上游不证明真实 Google 服务兼容。

已知维护缺口（记录 0.1.25 当时的状态）：非法代理在插件装载期抛 `ProxyConfigError`，需要通过宿主通用配置面修复——**该条已在 0.1.31 解除**，现在装载期只告警；宿主崩溃、没有明确子进程退出记录的运行目录不会自动回收；已有解压目录损坏且缺少有效可执行文件时不保证自动自愈。其余限制见[排障](reference.md#排障)。

尚未完成 **0.1.24 安装后的 Desktop GUI、真实上游生成、真实图片识别、非 Windows 实机验证**。未在本次执行真实登录 / 额度 / Credits 调用，未将历史记录升级为当前版验收。生产依赖漏洞审计不由上述检查覆盖。

普通新用户回合仍创建 ACP session 并重放完整历史；不提供跨进程会话恢复，不承诺 API 式角色层级、采样控制或延迟。`maxTokens` 仍忽略，`temperature` / `stop` 仍拒绝。ACP 原生工具保护仍是协议与生命周期约束，**不是 OS 沙箱**。

### 升级注意

- 更新后按部署方式重载 Host 与 Client；Desktop 按目标版本要求退出 / 重开。只刷新页面不足以升级后台。
- 默认双 worker 比单进程可能占用更多内存；资源受限时设置 `maxConcurrentSessions: 1`。池容量不提升上游账号额度。
- 无目录时先连接 / 登录，不再依赖“首次对话登录”占位项；旧 `server-default` 路由保留兼容。
- CLI 额度与 ACP 连接认证分别检查；ACP 登录不替 CLI 登录。已有缓存不代表上游持续可用。
- 不为迁移批量删除旧 `_MEI*` 或修改 ACL；先确认所属进程已停，再人工处理未知历史目录。
